Qamrovchi daraxt protokollari Spanning Tree Protocols

Asosiy atamalar
  • Halqa (loop) — kadr aylanib qoladi, tarmoq bo‘g‘iladi
  • STP — ortiqcha kanalni bloklab halqasiz daraxt yasaydi
  • BPDU — kommutatorlar almashadigan boshqaruv kadri
  • Root bridge — daraxt ildizi: eng kichik bridge ID
  • Bridge ID — ustuvorlik (priority) + kommutator MAC manzili

1. Halqa nima qiladi?

1-rasm. Ko‘prik kadrni o‘zgartirmaydi, hop hisoblagichi yo‘q

  • MAC jadval har safar buziladi — manzil sakraydi
  • Har o‘tishda kadrning nusxasi ikkiga ko‘payadi
— 1 —

2. STP nima qiladi?

2-rasm. 802.1D halqani daraxtga kesadi

3. BPDU

  • Root ID — jo‘natuvchi root deb bilgan ko‘prik ID’si
  • Root path cost — root’gacha eng arzon yo‘l narxi (root’da 0)
  • Designated bridge ID — segment egasi (ustuvorlik + MAC)
  • Designated port ID — port ustuvorligi + port indeksi
— 2 —

4. Root bridge tanlash

3-rasm. Ustuvorlik teng bo‘lsa — kichik MAC g‘olib

Boshida har kommutator o‘zini root deb biladi. Keyin BPDU’ni faqat root hosil qiladi, qolganlar uzatadi.

5. Port rollari

  • Root’da hamma port — DP (designated)
  • Har root’siz ko‘prikda eng arzon port — RP (root port)
  • Har segmentda eng arzon ko‘prik — designated bridge, uning porti — DP
  • Qolgani — AP (alternate), data bloklanadi

8. O‘tish va forward delay

Qoida: blocking → forwarding = 2 × 15 = 30 s. Taymerlar: Hello 2 s · MaxAge 20 s · FwDly 15 s.

Xulosa

  • STP zaxira yo‘lni bloklab halqani yo‘qotadi (802.1D)
  • Eng kichik bridge ID → Root; narx teng bo‘lsa ID, keyin port ID hal qiladi
  • Rollar: DP · RP faol, AP bloklangan
  • STP 5 holat, forward delay 15 s → 30 s; RSTP 3 holat
  • MSTP: VLAN → instance, bir necha trunk orasida yuk taqsimlash

Tekshirish

  1. Bridge ID nimadan tuziladi? — ustuvorlik + MAC
  2. Forward delay va to‘liq o‘tish? — 15 s va 30 s
  3. RSTP holatlari? — discarding, learning, forwarding
  4. H3C’da 1 Gbit/s narxi? — 20
